LOG 003 // QUADRUPED / DEPLOYMENT

Sim2Real Loop — 四足机器人 Sim2Real 部署闭环记录

把一条在 Isaac Lab 里训练的四足步态策略，完整带到实机上跑起来。 这篇记录整个链路上真正花时间的地方——大部分都不在"训练"这一步。

05 MIN READ
  • ISAAC LAB
  • MUJOCO
  • SIM2REAL
  • ONNX

01为什么先谈闭环，再谈指标

仿真里 reward 曲线再漂亮，只能说明策略适应了那个仿真。真正的验收标准是一条闭环： 训练 → 导出 → 中转验证 → 实机运行 → 数据回流。闭环走通一次之后， 后面每一次迭代都有了可靠的参照系；走不通，指标只是自我安慰。

所以这次我把目标定义成"让策略在真实设备上稳定站立并行走一分钟"， 而不是"训练到某个 reward 值"。目标变了，整个工作的重心自然就从调参转向了工程链路。

02Sim2Sim 是最便宜的保险

从 Isaac Lab 直接上实机的风险太高，中间加一层 MuJoCo 做 Sim2Sim 验证非常值得。 两个仿真器的物理引擎不同，能在这一步暴露的问题包括：观测向量的拼接顺序、 角度单位（弧度还是度）、默认关节角偏移、控制频率与动作缩放。

我的经验是：实机上的"翻车"，八成在 Sim2Sim 阶段就能提前复现。 MuJoCo 里走不好的策略，不要抱侥幸心理上真机。

03导出与实机侧的对齐

策略用 ONNX 导出，部署侧只依赖 onnxruntime，不需要拖着整个训练框架。 导出时最容易忽略的是观测归一化常数——它们必须与训练时完全一致， 我的做法是把它们和模型一起固化下来： 

# 观测归一化与动作缩放，随模型一起落盘
obs_scales = {
    "ang_vel":   0.25,
    "gravity":   1.0,
    "joint_pos": 1.0,
    "joint_vel": 0.05,
}
action_scale = 0.25
default_joint_pos = [0.1, 0.8, -1.5, ...]  # 与训练环境一致

实机侧按同样的顺序、同样的缩放拼观测。任何一项对不齐， 策略的输出都会看起来"像是坏了"，但其实模型没有任何问题。

04上机检查清单

每次上机前过一遍，顺序执行，任何一项不通过就停下：

  • 急停开关在手边，且当天测试过；
  • 先做零动作 dry-run：策略输出接死为默认关节角，确认通信链路与控制频率正常；
  • 核对关节限位与扭矩上限，宁可保守；
  • 机器人吊装或有人保护，第一次不允许直接放地上；
  • 动作幅度从 30% 起步，逐步放开到 100%；
  • 全程录制关节状态与策略输入输出日志。

05数据回流：闭环的最后一段

实机日志带回来之后做两件事：一是把真实观测序列喂回策略离线复算， 确认实机上的动作确实是模型算出来的（排除部署侧 bug）； 二是对比真实关节响应与仿真响应的差距，反过来修正仿真的执行器模型与域随机化范围。

闭环的意义在于：每一次失败都能定位到链路上的具体一环，而不是笼统地归咎于"Sim2Real gap"。

这条链路第一次走通花了很久，但之后每次迭代都快得多。 工程上的慢，往往是一次性的；绕过工程的快，每次都要重新付费。
