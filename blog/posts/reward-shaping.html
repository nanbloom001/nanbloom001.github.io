Reward Shaping — 奖励函数设计笔记

奖励函数是把"想要的行为"翻译成"可测量的信号"的过程。 翻译得不好，策略会精确地优化你写下的东西——而不是你想要的东西。

04 MIN READ
  • 强化学习
  • REWARD
  • 实验方法

01奖励项的三种角色

我习惯把奖励项分成三类，每一项写下来之前先问自己它属于哪一类：

  • 任务项（task）：定义"成功"本身，比如跟踪速度指令的误差。没有它任务不成立；
  • 风格项（style）：塑造"怎么完成"，比如步态对称性、抬脚高度。它们让行为看起来合理；
  • 正则项（regularization)：抑制不想要的副作用，比如动作变化率、关节扭矩、能耗惩罚。

分类的价值在于调试时的定位：行为不对，先查任务项；行为难看，动风格项； 动作抖、扭矩爆，调正则项。混在一起写，出了问题只能盲调。

02Reward hacking 的常见姿势

策略是最诚实的优化器，奖励里所有的空子它都会钻。我自己遇到过的几种： 为了刷 air-time 奖励原地快速抖腿；为了躲避碰撞惩罚干脆趴着不动； 速度跟踪项权重过低时，学会"看起来在走但原地打滑"。

看到一个诡异行为时，先别怀疑算法——把它当成一面镜子，照出奖励函数里真实写着的东西。

对付 hacking 最有效的不是加更多惩罚，而是让任务项本身更难被绕过： 比如用脚底接触序列约束步态，而不是单纯奖励 air-time。

03一次只动一个

奖励权重的调整我强制自己遵守两条纪律：一次实验只改一个权重； 每次改动前把预期写下来（"提高 X 应该让 Y 变化"）。 结果与预期不符时，这条记录比 tensorboard 曲线更有信息量。 

# 每组实验的奖励配置独立存档，可回溯
rewards = {
    "track_lin_vel":  1.0,    # task
    "track_ang_vel":  0.5,    # task
    "gait_symmetry":  0.3,    # style
    "foot_clearance": 0.2,    # style
    "action_rate":   -0.01,   # reg
    "joint_torque":  -1e-4,   # reg
}

04什么时候停手

判断标准只有一个：行为对了就停，不要继续追 reward 数值。 reward 是训练的手段，不是产品的指标。行为已经满足需求时， 多出来的那点 reward 提升往往来自过拟合仿真的细节——它们在 Sim2Real 的时候会变成负资产（这一点在 LOG 003 里展开）。
